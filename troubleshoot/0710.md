In Node.js and Bun, `process.argv` is an array that contains all the command-line arguments passed when the process was launched. However, the first two elements are always system-level paths, not the arguments the user typed:

1.  `process.argv[0]`: The path to the runtime executable (e.g., `/usr/local/bin/bun` or `/usr/local/bin/node`).
2.  `process.argv[1]`: The path to the script being executed (e.g., `/path/to/claude-code-src/src/entrypoints/cli.tsx`).

By calling `.slice(2)`, the code strips away those first two elements, leaving only the actual flags and arguments that the user provided to the CLI (like `-p` or `--init-only`). 

For example, if you run:
`bun ./src/entrypoints/cli.tsx -p "hello"`

`process.argv` looks like this:
`["/usr/local/bin/bun", "/.../cli.tsx", "-p", "hello"]`

And `process.argv.slice(2)` becomes:
`["-p", "hello"]`

### 1. What does `state` represent here?

The `state` object (and the global `STATE` constant) is the **central in-memory database/store for the active Claude Code session**. 

Because a CLI run is a single process, this object serves as a single source of truth that tracks:
*   **Session Lifecycle & Metadata:** The unique `sessionId`, parent sessions, start times, and which project directories are active.
*   **Usage & Telemetry:** Running totals of API cost in USD, input/output tokens used, tool execution durations, and how many lines of code have been added/removed.
*   **Global Config Flags & Overrides:** Environment details, user permissions, chrome/browser integration states, and target models.
*   **Active Features:** Running background cron tasks, loaded MCP tool configurations, and system prompt caches.

### 2. Why can it be updated if it is declared with `const`?

In JavaScript and TypeScript, the `const` keyword does **not** make an object immutable (unchangeable). It only prevents **reassignment** of the variable reference itself.

#### Reassignment vs. Mutation

*   **Reassignment (Blocked by `const`):** You cannot point `STATE` to a completely new object.
    ```typescript
    // This will throw a syntax error:
    STATE = { originalCwd: '/new/path', ... } 
    ```

*   **Mutation (Allowed by `const`):** You are allowed to read and modify the properties *inside* the object that the constant points to.
    ```typescript
    // This is completely valid:
    STATE.sessionId = randomUUID() as SessionId;
    STATE.planSlugCache.delete(STATE.sessionId);
    ```

For `const` to make something completely unchangeable, the object itself would have to be frozen (e.g., via `Object.freeze(state)`), but since this object's entire purpose is to track live session updates as they happen, it is intentionally left mutable.
